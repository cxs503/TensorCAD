# GAP-CAD-C1-5415-PARAM-REBUILD — 参数化 DTMB 5415 可微重建（返修轮 1 / m17472）

原单 m17352 交付经 maturity_gate 复核仅 L1。本轮**先复算再修**：三个真缺陷被定位并修好，验收
判据从「1/3 过」变为「2/3 过 + 1 项如实 FAIL 并附逐条原因」。所有数字由
`artifacts/m17472_5415_param/*.json` 程序化生成（零手抄），本文件只做引用。

## ① 案例介绍

DTMB 5415 标模，数据源 = Zenodo《Design-Space Dimensionality Reduction Benchmark Dataset – DTMB
5415 Hull》(Serani, Palma, Wackers, Quagliarella, Gaggero, Diez)：**9001 配置 × 27 归一化设计变量**
（[-1,1]），每配置 2250 全尺度曲面点（Lpp=142 m）。本地源
`/root/ship-data-official/dtmb5415/DTMB5415-database.mat`，1086721690 B，
sha256=`16b14ba5…364bee2`（记录在 `tensorcad.dtmb5415.DATASET`，运行工件里回显）。第 0 列=基准
5415，与平台 `DTMB5415_Hull_exact.stl`（sha256 `d40b17b1…`，164926 面）包围盒逐位一致。

几何参数表（模型尺度 → 全尺度，λ=142/5.720=24.8252，仅取数据集 README 表，不反解）：

| 量 | README（模型尺度） | 全尺度换算 |
|---|---|---|
| Lpp | 5.720 m | 142.0 m |
| B | 0.760 m | 18.867 m |
| T | 0.248 m | 6.157 m |
| ∇ | 0.549 t @ ρ=998.5 kg/m³ | 8412.0 m³ |
| Cb | — | 0.5100 (`∇/(L·B·T)`) |

模型：位移场 `d(v)=Φ·(C2·[v, vech(v⊗v)])`，Φ=前 40 PCA 模态（fit 集 7200 配置，方差 97.84%）；
`v=0` 精确回基准型；`(girth,station)` 指标空间三次样条双三次细化到 49×133/面片 + 镜像整船。

## ② 怎么做的

1. **复算优先**：先跑 `verify_shipped_model.py` 把「交付物」和「拟合器」对表 → 抓到
   **缺陷 1（线性项双计）**：`_amplitudes` 写成 `C1 v + C2 [v, vech]`，而 `C2` 的 405 列里
   **前 27 列就是 v 本身**（`quadratic_features` 的 `[v, vech]` 拼接），于是线性位移被算两遍。
   后果：交付模型留出集 RMS **0.8330 m**，而同一个 npz 在拟合器里是 **0.2516 m**（差 3.31×）；
   20 个真实配置几何门只有 6 个过。修法=`_amplitudes`/`_d_amplitudes` 只用 `C2`（npz 里 `C1`
   保留为纯线性模型 M1 诊断用），npz 未改（数组逐位相同，缺陷在代码不在数据）。
2. **抓缺陷 2（镜像因子双计）**：体积梯度解析值恰好是中心差分的 **2.0000 倍**
   （如 mode0：−226.511 vs −113.267）。`V=2·Σ 0.5(A_i+A_{i+1})·dx_i` 的 2 已经含在梯形权重
   `dV_dA=dx_{i-1}+dx_i` 里，代码末尾又整体 `G*=2.0`，导致 A 通道多一倍。修法=把 2 只加在
   `dV_dX`（x 权重）通道上。
3. **抓缺陷 3（水线自证 + 单位滑移）**：原 `WATERLINE_Z=6.055` 声称「反解 ∫A dz = 8412 m³」，
   但推导式写的是 `0.549 t / 998.5 kg/m³`（t 没换成 m³）→ 目标体积差 1000 倍，且水线本该是
   README 吃水。修法=`WATERLINE_Z = DRAFT_M = 0.248×λ = 6.1566 m`（物理吃水），排水体积改为
   **测量量**，消除「调水线凑体积、再拿体积验收水线」的循环；`SCALE_LAMBDA`/`DRAFT_M` 公开导出。
4. **补齐 round 0 缺失的入口**：`tools/dtmb5415_param/verify_geometry.py`（模块 docstring 早就
   引用它但文件不存在）做 Cb/L/B/T/∇ 对标表；`tensorcad/dtmb5415_cli.py` + console script
   `tensorcad-dtmb5415` 把模型接到命令行（`--config-index` / `--design-vector` / `--stl` /
   `--gradient` / `--gate`）。
5. **工件落地**：round 0 的 9 个运行工件写在 `runs/` 目录，被提交门禁整体滤除 → 本轮全部写到
   `artifacts/m17472_5415_param/`（含 3 张图 + 2 张表 + 4 个 JSON + 重拟合 npz）。
6. 复现（合计 < 2 min，本机执行；>10 min 的重计算规矩未触发）：
   `PYTHONPATH=. python3 tools/dtmb5415_param/fit_design_space.py`（87.7 s，可选，npz 已入库）→
   `run_acceptance.py`（27.5 s）→ `verify_geometry.py --out artifacts/m17472_5415_param`（11.5 s）→
   `verify_shipped_model.py --n-configs 400 --out artifacts/m17472_5415_param`（19.1 s）→
   `PYTHONPATH=. python3 -m pytest tests/test_dtmb5415_param.py -q`（17 passed, 4.6 s）。

## ⑤ 注意点（踩过的坑）

1. **自洽的梯度校验抓不到错的模型**：round 0 的 `vertex_jacobian_exact=True`（1.44e-08）是因为
   「解析导数」与「同一个错误前向模型的差分」比——恒等式永远成立。**必须先用外部数据（这里=
   数据集真实配置）钉住前向模型**，再谈可微性。本轮把它做成回归测试
   `test_no_double_counted_linear_block` + `test_shipped_model_holdout_accuracy`。
2. **`C2` 的列约定**：`quadratic_features` 返回 `[v, vech(v⊗v)]`（27+378=405），线性项在
   `C2` 里；`C1` 是另一套线性模型的系数。任何「C1 v + C2 feat」写法都是双计。
3. **npz 里 `beam_m` 是半宽**（10.2695 m），全船宽 20.539 m。round 0 用它算「%船宽」把误差放大
   2 倍；本轮加 `beam_full_m` 并在验收表里分开列。
4. **`runs/` 目录的工件不会进仓库**（round 0 的 9 个工件就是这样丢的）→ 运行工件一律写
   `artifacts/<mission>/`。
5. 模型适用范围：`[-1,1]^27` 的立方体内并非处处有效（均匀抽样 8/20 过半宽为负）；有效域是
   数据集 9001 配置张成的低维流形邻域。
6. 重计算规矩：本单全部步骤单步 <90 s，无需集群；若要全 9001 配置扫描应走 cluster_queue。

设计点做几何投影约束（未在本单预算内执行，如实留档）。
