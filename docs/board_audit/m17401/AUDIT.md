## 3. Why L4 is refused (three independent reasons)

1. **The acceptance criterion is met 0/3.** The mission goal is "3 **real** STEP files → mesh, volume vs
   **CAD nominal** <1 %". The 4 meshed solids are fixtures generated by `tools/step_samples.py`; the
   subject's own `provenance.json` states it verbatim: *"authored fixtures: geometry is defined in closed
   form in tools/step_samples.py … not downloaded CAD parts"*. The one real third-party file has no
   `MANIFOLD_SOLID_BREP` (it is a wireframe/sheet model) and is refused — correctly and honestly, but that
   means **zero** real CAD solids were meshed.
2. **The reference is self-authored.** Nominal volumes are closed forms written in the same repo, not a
   CAD kernel's reported volume. They are analytically exact (and the auditor independently recomputed
   them from the geometry table), so the *mesh* validation is sound; but this validates the tessellator
   against maths, not the reader against a commercial kernel's semantics.
3. **No machine-adjudicated benchmark case exists.** `SELECT … FROM tensor_benchmark_cases WHERE
   anchor_slug='GAP-CAD-B1-STEP-READER'` → **0 rows**. The only TensorCAD anchor registered is
   `GAP-CAD-T1-BASELINE-FLEET`. The acceptance numbers live only in the mission goal and the delivered
   artefacts, so there is no DB judge for this anchor.

Note the honesty is not in question: the subject's report and `GAP-ANCHORS.md` both say
external validation is `WITHHELD`. The gap is coverage, not truthfulness.

## 4. Severity-ranked findings

**F1 — blocking for L4 — external/real-CAD benchmark missing.** 0/3 real solids meshed; nominals self-authored;
no `tensor_benchmark_cases` row. *Evidence*: C4 refusal message, `refs/provenance.json`, C7 `n_rows=0`.
*Remediation*: mesh at least one genuine commercial-kernel solid export (any FreeCAD/OCP/Inventor
`MANIFOLD_SOLID_BREP` part with a published or kernel-computed volume), and register a benchmark case row
for the anchor so future audits have a DB judge.

**F2 — minor — `complete` flag semantics.** On an internally inconsistent file the import returns
`complete=True` together with `watertight=False`, `boundary_edges=8`, `volume_m3=None`. The volume is
correctly withheld, but a consumer keying on `complete` alone can mistake an unclosed mesh for a finished
import. *Reproduce*: `verify_claims.py` check C6. *Suggested fix*: document `complete` as "every face
tessellated", or define `complete = faces_ok and watertight`.

**F3 — info — convergence headline.** Ratio sequence is 3.69 / 3.85 / 3.92 / 4.00; the report quotes the
finest pair (3.999) as the order. Asymptotic second order is genuinely supported; the single number is the
best-case pair and should be quoted as such.

**F4 — info — anchor has no benchmark-registry entry** (same root cause as F1 reason 3). TensorCAD has 1
registered anchor; this gap will keep recurring for every TensorCAD anchor until rows are registered.

## 6. Independence limitations (stated honestly)

- The auditor read the subject's own artefacts and re-ran the subject's own code; the volume
  re-integration is independent (separate OBJ + separate divergence script) but both sides measure the
  same tessellation produced by the subject's tessellator. A shared-parameter bug (e.g. the angular
  sampling strategy) would show up in both.
- The closed forms were re-transcribed from the geometry table in the subject's doc, then recomputed; a
  wrong *geometry description* that matches its own fixture would not be caught by this method. What it
  does catch — and did — is the mapping fixture → mesh → volume and the declared error magnitudes.
- Fixtures being generated by the subject means "reader handles a real-world file" is **untested**, which
  is exactly finding F1.
