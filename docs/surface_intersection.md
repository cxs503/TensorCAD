# Surface--surface intersection

`tensorcad.surface_intersection` returns the *curve* along which two surfaces meet, not a
yes/no answer about facets. It closes `GAP-CAD-002` in
`docs/oss_inventory_cad/GAP-ANCHORS.md`, whose acceptance criterion is explicit: cylinder--
cylinder arc length within **3%** of the analytic value, every point on both surfaces to
`1e-9 L`.

```python
from tensorcad import CylinderPatch, cylinder_implicit, surface_surface_intersection

curve = surface_surface_intersection(
    CylinderPatch(radius=1.0, height=3.0),      # z-axis cylinder, u = angle, v = z
    cylinder_implicit(1.0, axis="x"),           # the same cylinder about x
    samples=(128, 32),                          # grid cells in (u, v)
)
curve.total_length                              # 15.2807077 m, the Viviani pair
```

## Method

The problem is one dimensional in space but two dimensional in *parameters*. For a
parametric surface `S(u, v)` and an implicit one `f(x) = 0`, the function

    g(u, v) = f(S(u, v))

vanishes exactly on the intersection, so the curve is the zero level set of a scalar
field on a rectangular parameter domain. The module samples `g` on a grid of
`samples = (u_cells, v_cells)`, finds every grid edge where the sign changes, bisects
along that edge to machine precision to place the crossing, and chains crossings cell to
cell through the edge keys. Two consequences matter:

* every output vertex is a **parameter pair**, so it is *on* the parametric surface to
  round-off by construction (the residual that is reported is `f` at that point);
* branch and loop structure comes from the cell topology, not from a distance test --
  which is what makes it work on the Viviani pair, where the two branches cross each
  other and a proximity test would happily jump between them.

Chaining by edge key rather than by proximity is the reason the saddle case
(`grad g = 0`, four crossings in one cell) is resolved by the cell-centre sign instead of
by guessing.

### Periodic parameters are the trap

A cylinder's `u` and a sphere's `u` are angles: `0` and `2 pi` are the same meridian.
Those surfaces declare `periodic = (True, False)`, the grid wraps, and the seam edge is
bisected in *unwrapped* parameters (`2 pi + eps`, not `eps`), so a loop that closes across
the seam keeps its closing chord. Without the flag, the loop comes back as an open chain
and loses exactly one segment -- which on an `n`-point circle is an `O(h)` error that looks
like a discretisation problem and is not.

A *clamped* parametric patch (every `NURBSSurface`, whose seam is a duplicated row of
control points) closes positionally rather than through a shared edge key. That path is
detected on position and only the seam gap is added as a chord, because re-refining that
last step would average two parameters a whole domain apart.

### Length

A chord sum is short for a curved arc: the per-segment chord error behaves like
`kappa**2 h**3 / 24`, so the relative error is `O(h**2)`. `refine_levels` inserts a
midpoint that a Newton step in parameter space projects back onto `g = 0`, halving `h` per
level. Both the raw chord sum (`chord_length`) and the refined length (`length`) are
reported; the convergence table below is the measurement of that claim, not an assertion.

acceptance bound is 3%, i.e. this is roughly 2633x inside it.

## Limitations

* **Tangential contact is not found.** A plane grazing a sphere meets it in a point, so
  there is no sign change; the march returns a rounding-scale trace around the pole
  (`< 1e-6 L`), not a curve. `tests/test_surface_intersection.py` pins that behaviour so it
  cannot silently turn into a fake answer.
* **Coincident surfaces raise.** If `g` vanishes on the whole patch the intersection is a
  surface, not a curve; the module raises `SurfaceIntersectionError` instead of returning a
  cloud of meaningless branches.
* **A feature thinner than one cell is invisible.** Raising `samples` is the remedy, and it
  is the caller's call: the module cannot detect what it never sampled.
* **Curves that leave the patch are truncated** at the domain boundary and reported as open
  (`closed == False`).
* The implicit side is read as a *signed distance*, so residuals are lengths. The
  `*_implicit` factories in the module satisfy `|grad| = 1`; a raw quadratic form
  (`x**2 + z**2 - R**2`) would give residuals in length squared.
* No surface--surface *trimming* or patch stitching is provided: this returns curves, and
  turning them into B-rep edges is the next step, not this one.
