**Defect 2 — the scale-slip detector stopped auditing the dissent.**  Round 1 attributed
the KVLCC2 `Bwl 580` typo with a power-of-ten scan of the *family value*.  Round 3 gave
that row a second lineage printing the corrected 58 m, so the majority cluster became
the corrected value, the family closes, and a detector that only inspects the winning
numeral reported *no typo* — for a source that still prints 580 in two of its five
entries.  The finding did not become false; it moved into `family_disagreement.dissent`,
where nothing was looking.  Two tests had been parked as `xfail` on exactly this.

## 5. Traps worth recording

1. **A cache of a pure function is a second source of truth.**  The repair is not "be
   careful when merging": `merge_into` now refreshes `closure`/`adjudication` itself and
   `refs_freshness.py check` fails the build if any cached block stops following from
   `report`.  A new round that forgets to refresh cannot be merged silently.
2. **`adjudicate` writes into the report it reads** (`closure_defect` on the cells), so the
   freshness check recomputes on a deep copy — asking "is this stale?" must not rewrite
   the artefact being asked about.
3. **Independence is not what the closure test measures.**  A table that closes on its own
   digits proves it was transcribed consistently, never that a second body measured the
   hull; the KVLCC2 `580` case is a table that *reproduced* a typo across two publishers.
4. **The dissent is the audit trail.**  Majority voting is right for the value and wrong
   for the audit: the losing numerals are the only place a systematic typo shows up once
   enough publishers copy the correction.
