## ① Problem and reference provenance

Three-dimensional Taylor–Green vortex on the periodic box `[0, 2π]³`:

```
u₀ = A sin x cos y cos z,   v₀ = −A cos x sin y cos z,   w₀ = 0
```

Taylor & Green (1937), *Proc. R. Soc. Lond. A* **158**(895), 499–521.

Three reference tiers are shipped, in order of decreasing closed-form-ness:

| tier | field | why it is a reference |
|---|---|---|
| `TaylorGreenMode` | z-invariant mode, `lap ψ = −2ψ` ⇒ convective term is a pure gradient | **exact** NS solution, `u = A e^{−2νt}(sin x cos y, −cos x sin y, 0)`, `p = (A²/4)e^{−4νt}(cos 2x + cos 2y)` |
| `BeltramiABC` | `u = a(sin kz + cos ky, sin kx + cos kz, sin ky + cos kx)` | **exact**, `curl u = k u` ⇒ `(u·∇)u = ∇(|u|²/2)` ⇒ `u(t) = u₀ e^{−k²νt}`, `p = −|u|²/2`; genuinely z-dependent |
| `TaylorGreen3DSeries` | the classic z-dependent vortex | its convective term is **not** curl-free ⇒ no closed form; reference = time-Taylor series `u(x,t) = Σ_{n≤N} uₙ(x) tⁿ` |

**Zero hand-copying.** No table is transcribed: the series coefficients are
generated by the projected Navier–Stokes recursion
`(n+1)uₙ₊₁ = −P[Σ_{p+q=n}(u_p·∇)u_q] − ν|k|²uₙ` in a complex Fourier basis, and
every number in this report is read out of `docs/taylor_green_3d/crosscheck.json`
/ `metrics_table.json`, which the script writes.

## ② Method and implementation

* **Reference generation** (`tensorcad/taylor_green.py`): sparse complex Fourier
  modes per Taylor order (`Mode → Vec`), Leray projection per mode, truncated at
  `|k|∞ ≤ N+1`. Defaults `N = 12`, `A = 0.25`, `ν = 0.01` — an amplitude chosen so
  the series stays comfortably inside its radius of convergence over `t ∈ [0,4]`
  (coefficient ratio `‖u₁₂‖/‖u₁₁‖ = 0.198`).
* **Verification, three independent routes**:
  1. *analytic residuals* — `ns_residual`/`curl_eigen_residual` with hand-derived
     derivatives for the two closed forms (`~1e-16`), `divergence` for the series;
  2. *order-completeness* — `defect_spectrum()` evaluates
     `du/dt + P[(u·∇)u] − ν∇²u` coefficient-by-coefficient on the truncated
     series; orders `0…N−1` balance to `≤1e-20` and the first non-zero entry sits
     at `n = N`;
  3. *independent physics* — a Fourier pseudo-spectral RK4 DNS (`32³`, 2/3-rule
     dealiasing, `dt = 0.04`) shares no code with the series. It is the check that
     catches sign or normalisation errors: a wrong convection sign shows up as an
     O(1) energy mismatch, not as a residual.
* **Consumption surface**: `case_spec()` (dimensionless parameter block),
  `metrics_table()` (`E`, `Z`, `dE/dt`, series defect spectrum), `mode_table()`
  (compact exact Fourier modes at a time), `sample_grid()`, `compare_metrics()`
  (relative errors + 8 % band flagging), `fit_decay_rate()`.
* **One-command reproduction**:
  `python examples/taylor_green_3d/make_reference_bundle.py` and
  `python -m pytest tests/test_taylor_green.py -q` (16 passed, 7.5 s).

## ⑤ Points to note (traps, limits, applicability)

* **The series has a finite radius of convergence.** At the default amplitude the
  coefficient ratio is 0.198, and `E(4)` already carries a `1.4e-6` truncation
  error. Do not evaluate beyond `t ≈ 4` with `N = 12`, and never extrapolate: the
  polynomial diverges once `t` leaves the disc of convergence (with `A = 1`,
  `N = 12` the same code produces nonsense at `t = 2` — a real trap we hit).
* **Amplitude scales the radius.** Time scales with `1/A`, so `A = 0.25` buys a
  usable window four times longer than `A = 1`. Choosing a large amplitude `A`
  for a "stronger" case breaks the reference, not the solver.
* **`dE/dt = −2νZ` holds only to truncation error** for the truncated polynomial
  (`~1e-10` at `t = 2`, `O(1e-5)` relative at `t = 4`); tests assert it inside
  the trusted window rather than everywhere.
* **The z-invariant mode is a 2-D plane**, not a three-dimensional check — the ABC
  flow and the series are the tiers that exercise a 3-D solver branch. Do not let
  a solver pass the 2-D tier and claim a 3-D validation.
* **Pressure sign.** The z-invariant pressure is `+(A²/4)e^{−4νt}(cos 2x + cos 2y)`
  in this sign convention; the opposite sign doubles the convective term instead
  of cancelling it, which is exactly what the residual test caught during
  development.
* Reference data is plain JSON with a per-file `sha256` manifest
  (`bundle_manifest.json`) — a solver run can pin the exact artefact it used.
