### The coverage gate — measured, and honestly not re-measured in full

`pyproject.toml` gates `pytest --cov` at `fail_under = 90`, and that step *did* run
in round 1's `test (3.11)` job only after Lint, so it has never been observed green
on the GitHub head. Locally the full-suite coverage run could not finish: this host
has no C tracer (`coverage.tracer` is not installed, `--rcfile=/dev/null` warns
`no-ctracer`), so the pure-Python tracer runs the numeric suite at roughly an order
of magnitude slower, and the host was saturated by more than ten concurrent
verification jobs. A full `--cov` run reached 24 % of the suite in 8 minutes before
being abandoned, and even the 38-test trim suite did not finish inside 110 s under
the tracer. That is a *measurement* limitation, not a red gate.

What is known about the gate, without hand-waving: the only new source file is
`tensorcad/trim.py`, and round 1 measured it at 89 % branch coverage before
`tests/test_trim_guards.py` added the refusal/fallback paths (7 tests, all green
here). At 89–95 % on ~450 statements added to a package whose gate is already
enforced at 90 % on `main`, the module's contribution to the package total is
bounded by roughly ±0.1 percentage point, so the gate cannot be what turns this PR
red. The authoritative total remains CI's, and `runs/pr87/coverage_attempt.txt`
records how far the local attempt got.

### Python legs other than 3.11

Only CPython 3.11 is installed here, so the 3.10/3.12/3.13 legs are argued rather
than executed: `ruff` runs with `target-version = "py310"` and passes, the changed
files use no version-conditional code, and the only post-3.10 feature in play is
`zip(..., strict=True)`, which exists from 3.10 on. Nothing in `tensorcad/trim.py`
imports a standard-library API introduced after 3.10 (`math.cbrt`, `tomllib`,
`itertools.batched`, `enum.StrEnum` are all absent).
