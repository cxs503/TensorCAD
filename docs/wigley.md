# The Wigley parabolic hull

`tensorcad.wigley` adds the standard analytic ship-hydrodynamics benchmark hull to the
geometry kernel. It exists for two reasons, and the second is the interesting one.

1. **It has closed-form hydrostatics.** The half-breadth is a low-order polynomial, so
   every hydrostatic quantity a solver reads has an elementary value. A mesh generated at
   any resolution can be judged against arithmetic instead of against another mesh.
2. **It is fair at the ends.** The family TensorCAD shipped first — the sine taper of
   `tensorcad.hull` — arrives at the stem and the stern with an *infinite* waterline
   slope. The Wigley hull arrives with a finite slope and a finite curvature. Carrying
   both families means the fairness machinery in `tensorcad.curvature` has a control that
   is meant to pass and a specimen that is meant to fail, on the same mesher and in the
   same coordinate frame.

## Definition

In the frame of `tensorcad.hull.COORDINATE_FRAME` (`x` from the aft end, `z` positive up,
`z = 0` at the design waterline, keel at `z = -T`):

```
b(x, z) = (B/2) · (1 − (2x/L − 1)²) · (1 − (z/T)²),      0 ≤ x ≤ L,  −T ≤ z ≤ 0
|y| ≤ b(x, z)
```

The keel is a line of zero breadth, the design waterline is the widest section (`B`), and
the body is fore/aft symmetric with no transom, no bulb, no flare and no parallel body.
Defaults are `L = 10 m`, `B = 1 m`, `T = 0.625 m`, i.e. `B/L = 0.1` and `T/L = 0.0625`,
the proportions the hull is normally quoted at.

## Closed forms, derived

Because `b` is separable, `b = (B/2)·f(x)·g(z)` with `f = 1 − (2x/L − 1)²` and
`g = 1 − (z/T)²`, every integral over the volume factors into one integral in `x` and one
in `z`, and both are polynomials:

```
∫₀ᴸ f dx = 2L/3        ∫₋ₜ⁰ g dz = 2T/3        ∫₋ₜ⁰ z·g dz = −T²/4
```

| Quantity | Closed form | Value at `L=10, B=1, T=0.625` |
|---|---|---|
| displacement volume `∇` | `4LBT/9` | 2.777 777 8 m³ |
| waterplane area `A_w` | `2LB/3` | 6.666 666 7 m² |
| maximum section area `A_m` | `2BT/3` | 0.416 666 67 m² |
| LCB, LCF | `L/2` | 5 m |
| VCB | `−3T/8` | −0.234 375 m |
| block coefficient `C_b` | `4/9` | 0.444 444 44 |
| waterplane coefficient `C_w` | `2/3` | 0.666 666 67 |
| prismatic coefficient `C_p` | `2/3` (`A_m` contributes `2BT/3`) | 0.666 666 67 |
| wetted surface `S_w` | quadrature (no elementary antiderivative) | 14.879 063 m² |

`C_b = 4/9` for **every** dimension set — that is the property that makes the family a
benchmark rather than a design, and it is used as a test
(`test_block_coefficient_is_four_ninths_for_every_hull`).

### One arithmetic error worth recording

The first version of this module wrote `VCB = −9/16·T`. The correct evaluation of
`(−T²/4) / (2T/3)` is `−3T/8 = −0.375 T`; `−9/16 = −0.5625 T` is 50 % larger in
magnitude. The mesh immediately disagreed by `−33 %`, and the mesh was right. The closed
form is now pinned by an independent Simpson quadrature of the definition
(`test_vertical_centre_buoyancy_matches_quadrature`, 20 000 panels), and a second check
asserts it differs from the sine family's `−2T/5`, so the two sections cannot be silently
swapped. This is the argument for keeping a quadrature check next to every "exact"
formula: the formula was checked by reading it twice and stayed wrong.

## Verification against the mesh

Three grids, all quantities, signed error. Generated by
`examples/wigley/run_wigley.py` into `docs/wigley/results.json`; the table below is copied
from `docs/wigley/report.md`, which the same run writes.

| quantity | 41×13 (1 998 tri) | 81×25 (7 838 tri) | 161×49 (31 078 tri) |
|---|---|---|---|
| volume `∇` | −0.2360 % | −0.0590 % | −0.0148 % |
| wetted surface `S_w` | −0.0201 % | −0.0050 % | −0.0013 % |
| waterplane `A_w` | −0.0625 % | −0.0156 % | −0.0039 % |
| midship section `A_m` | −0.1736 % | −0.0434 % | −0.0109 % |
| VCB | −0.0580 % | −0.0145 % | −0.0036 % |
| `C_b` | −0.2360 % | −0.0590 % | −0.0148 % |
| `C_p` | −0.0625 % | −0.0156 % | −0.0039 % |
| LCB, LCF | 0.0000 % | 0.0000 % | 0.0000 % |

* Every error is **negative**: the loft is inscribed between stations, so a mesh cannot
  exceed the analytic surface. A sign flip would be a defect, and the run fails on one.
* The error is **second order**: refining both counts (which halves the spacing) divides
  the volume error by 4.00 and 4.00, measured, against 4 expected.
* `LCB`/`LCF` land on `L/2 = 5 m` to round-off at every grid, which checks the x frame
  and the sign of the x moments rather than the discretisation.
* The wetted-surface reference is not the error term: doubling the quadrature from 80 to
  160 nodes moves it by `4.3 × 10⁻¹⁵` relative, five orders below the finest mesh error
  (`1.3 × 10⁻⁵`). The quadrature is also cross-checked against an independent Simpson
  product rule in `test_wetted_area_matches_independent_simpson_product_rule`.

### Is the error under 3 %?

Yes, by a wide margin: the worst quantity at the default grid is the displacement volume
and the block coefficient at **0.236 %**, and nothing exceeds **0.015 %** at 161×49. The
verdict is stated per quantity in `docs/wigley/results.json` (`claims`), with the limits
that produced each verdict.

Note what this comparison can and cannot claim. The reference is the closed form of the
*definition*, not an experimental measurement: a Wigley hull is a mathematical object, so
"agreement with literature" would be a category error. What the numbers prove is that the
mesher, the hydrostatic integrator and the frame conventions reproduce the defining
formulas — i.e. that the pipeline is correct. The literature role of this hull is as the
*shared test geometry* for flow solvers; the geometry is what this module has to get right,
and that is what has been measured.

## Fairness at the ends

The waterline is `b(x,0) = (B/2)·(1 − (2x/L − 1)²)`, so

```
db/dx  = (B/2)·(−4/L)·(2x/L − 1)   →   ∓2B/L at x = L and x = 0     (finite)
d²b/dx² = −4B/L²                                                     (finite)
```

At `B/L = 0.1` the end slope is `0.2` (dimensionless: `0.2` in `1/m` for `L = 10 m`), and
it is *reached*, not approached through a singularity. The sine family, by contrast, has
`db/dx ∝ x^{−0.3}`: over seven decades of probe depth (`x/L = 10⁻² … 10⁻⁹`) its slope grows
**125.9×**, which is exactly the `10^{2.1}` an `x^{−0.3}` law predicts. Measured in
`docs/wigley/results.json` under `waterline_slope_near_stern`:

| x/L | Wigley secant `db/dx` | Wigley analytic | sine secant | sine analytic |
|---|---|---|---|---|
| 1e-2 | 0.198 | 0.196 | 0.444 | 0.310 |
| 1e-4 | 0.199 98 | 0.199 96 | 1.766 | 1.236 |
| 1e-6 | 0.200 000 | 0.200 000 | 7.030 | 4.921 |
| 1e-8 | 0.200 000 | 0.200 000 | 27.99 | 19.59 |
| 1e-9 | 0.200 000 | 0.200 000 | 55.84 | 39.09 |

At the same triangle budget (81×25, 7 838 triangles) the two families also separate in the
fairness audit of `tensorcad.curvature`:

| | Wigley | sine family |
|---|---|---|
| p50 dihedral | 0.582° | 0.521° |
| p95 dihedral | **3.573°** | **6.988°** |
| crease length fraction (> 15°) | **2.58 %** | **4.18 %** |

The median is unremarkable in both — most panels are fine — while the tail differs by a
factor of two. That is what a divergent end slope does to a mesh: it is invisible in the
average and dominant in the worst panels. Coarse-mesh crease statistics measure the mesh
more than the geometry (see `docs/fairness.md`), so these numbers are quoted as evidence
of a *comparative* difference at equal cost, not as an absolute quality grade.

## Using it downstream

```python
from tensorcad import WigleyParameters, generate_wigley, write_obj, write_offsets_csv

model = generate_wigley(WigleyParameters(length=10.0, beam=1.0, draft=0.625))
model.hydrostatics.block_coefficient        # 0.443396 (mesh) / 0.444444 (4/9, closed form)
model.validation.errors                     # []  — watertight, edge-manifold, V-E+F=2
write_obj(model.mesh, "wigley.obj")         # hand to a flow solver
write_offsets_csv(model.offsets, "wigley_offsets.csv")
model.to_dict(with_discretisation=True)     # JSON record, including the refinement estimate
```

The module-level analytic API (`tensorcad.wigley.analytic_hydrostatics`,
`analytic_volume`, `analytic_wetted_surface_area`, `analytic_relative_errors`,
`estimate_discretisation_error`) mirrors `tensorcad.hull`, and three of its names are
re-exported from the package as `wigley_analytic_hydrostatics` and `wigley_half_breadth`
to avoid colliding with the sine family's identically named functions.

## What this does not provide

* **A `Cb`-parameterised family.** `Cb` is `4/9` for the Wigley family by construction; it
  is a benchmark, not a design space. Choosing a `Cb` still needs the sine family plus the
  design loop, or a real hull-form series.
* **Appendages, transom, bulb, asymmetry.** None; the body is fore/aft symmetric with no
  stern closure but the parabolic taper.
* **A waterline other than `z = 0`.** Slicing at an arbitrary waterline is out of scope for
  the hydrostatic integrator in both families.
* **Resistance, stability or class rules.** Nothing hydrodynamic is computed here; the
  handoff is geometry and hydrostatics only.
* **A field-protocol adapter.** `tensorcad.geometry_field` has no `WigleyField` yet, so the
  curvature module can be pointed at the mesh but not at the analytic surface. The
  surface-level curvature is checked directly in the tests instead
  (`d²b/dx² = −4B/L²` by central difference on the analytic `b`).
