# The vectorised metrics backend and what it buys

Status: shipped with `GAP-CAD-D1-MESH-QUALITY-LIB` as the answer to the acceptance clause
*usable as a CI gate*. Written by mission `m21614`.

## 1. The problem the scalar path has

`tensorcad.meshquality.metrics` is pure Python: per cell it walks eight tuples for the
trilinear Jacobian, twelve edges, and twenty-four face angles. Measured on this host
(loongarch64, CPython 3.11): **~260 microseconds per hexahedron**. A 10^6-cell CFD mesh --
the size the FVM/solver consumers in this ecosystem actually hand over -- therefore costs
about four and a half minutes of measurement before a single threshold is applied. That is
not a gate.

## 2. What was added

`tensorcad/meshquality/numpy_backend.py`: the same arithmetic, evaluated on arrays of cells
(the corner/face/edge tables are *imported from* `.metrics`, so the two implementations
cannot drift apart). `tri`, `quad`, `tet` and `hex` are vectorised; `prism` and `pyramid`
deliberately are not (finite-difference Jacobians at seven/nine sample points, rare in the
meshes this library gates) and say so by raising on `backend="numpy"` instead of silently
falling back.

Every metric function gained one keyword:

| `backend` | behaviour |
|---|---|
| `"auto"` (default) | vectorised at >= 128 cells (`AUTO_NUMPY_MIN_CELLS`), scalar below |
| `"scalar"` | always the pure-Python reference |
| `"numpy"` | forced; raises on a kind that is not vectorised, or when numpy is missing |

`report.measure()` forwards the keyword, so the CLI and the gate follow it.

## 3. Agreement, measured (not asserted)

Two implementations of one contract are only useful if somebody checks them against each
other. `tests/test_meshquality_numpy_backend.py` compares every metric of every cell,
including the guard **patterns** (`NaN` positions, `inf` signs), on

* the canonical elements (cube, square, equilateral triangle, regular tetrahedron, right
  prism), where the ideal values must come out exactly (1.0 for `scaled_jacobian` of a
  cube/square/triangle, 1/sqrt(2) for a regular tetrahedron, 2^(-1/3) = 0.7937005 for
  Gmsh's `gmsh_icn` unit);
* randomly jittered hexahedra, the six-tetrahedron split of a cube, jittered quads and
  triangles, at 1 / 5 / 200 cells and on structured boxes;
* degenerate cases: a collapsed hexahedron (V = 0), an inverted tetrahedron (negative
  `min_sicn`), a triangle with a duplicated node;
* rigid motion and uniform scaling (metamorphic invariance: shape metrics unchanged, volume
  scales as s^3).

Residual differences and timings, generated by the run below on this host:

| kind | cells | scalar us/cell | numpy us/cell | speedup | max abs diff | guard patterns match |
|---|---:|---:|---:|---:|---:|---|
| `hex` | 512 | 475.0 | 19.26 | 24.7x | 0 | yes |
| `hex` | 8000 | 475.4 | 12.68 | 37.5x | 0 | yes |
| `hex` | 32768 | 476.0 | 14.25 | 33.4x | 0 | yes |
| `tet` | 384 | 426.8 | 67.82 | 6.3x | 2.22e-16 | yes |
| `tet` | 3072 | 431.3 | 25.90 | 16.7x | 2.22e-16 | yes |
| `tri` | 3200 | 15.0 | 3.17 | 4.7x | 1.11e-16 | yes |
| `tri` | 12800 | 16.4 | 3.75 | 4.4x | 1.11e-16 | yes |

Extrapolated from the measured per-cell cost, 10^6 hexahedra go from ~476 s to
~14.2 s (measured directly at 10^6 cells: **14.2 s**). The residual difference is
summation order inside dot products, i.e. round-off; it is bounded by the test tolerance
(1e-12 relative) and is four orders of magnitude below any threshold this library gates on.

## 4. Two defects this work found, and fixed

1. **`eta` was shadowed in the vectorised quadrilateral path.** The loop
   `for xi_c, eta_c in _QUAD_CORNERS` reused the name `eta`, which held the Gmsh metric, so
   the quad `eta` metric silently returned the corner coordinate 1.0 for every cell. Only the
   scalar-vs-vector cross-check could see it; the vectorised path agreed with itself
   perfectly. Fixed by renaming the loop variables.
2. **`min_angle`/`max_angle` of triangles and quadrilaterals depended on the *position* of a
   `NaN`.** Those two kinds called `min()`/`max()` on a tuple that can contain `NaN`, and in
   Python a `NaN` in the first slot wins while a later one is ignored (every comparison is
   `False`). Hexahedra and tetrahedra already filtered invalid corners, so the same
   degenerate cell got different angles depending on the cell kind. Both paths now use
   `_min_max_deg`, which drops invalid corners and reports `NaN` only when no corner is
   valid; `docs/mesh_quality.md` documents the convention. This is a behaviour change for
   degenerate triangles/quads, and it is the *documented* behaviour of `skewness` and of the
   hexahedral path rather than a new invention.

## 5. One limitation pinned, not papered over

The triangle `scaled_jacobian` comment claims the value is "signed by the winding so a
flipped triangle is negative". It is not: a triangle floating in 3-D has no intrinsic
orientation, and the scalar path computes `signed_area = 0.5 * dot(cross, unit(cross)) =
0.5 * |cross|`, which is never negative. `test_triangle_orientation_is_not_signed` pins the
actual behaviour (both windings give the same value), so the claim cannot come back.
Tetrahedra *do* carry a sign (signed volume) and their `min_sicn` does go negative; that is
tested.

## 6. What this does **not** do

It does not close the oracle half of the anchor's acceptance (comparison against Gmsh and
meshmagick). Those still cannot run on this host: the gmsh wheel is published for
x86_64/aarch64 only, VTK has no loongarch64 wheel (so meshmagick, which delegates to
`vtk.vtkMeshQuality`, cannot be installed either), PyPI publishes **wheels only** for both
(`gmsh` and `vtk` simple indexes contain no `.tar.gz`), and `deb.debian.org/debian-ports`
has no `gmsh` for `loong64`. What the library does instead is documented in
`docs/mesh_quality.md` section 5: the Gmsh/Verdict definitions are transcribed with
provenance, and the third-party runtime comparison that *can* run here (trimesh) is run.
The vectorised backend strengthens the *internal* cross-check from one implementation to
two; it does not substitute for an external oracle, and this document does not claim it
does.

## 7. Reproduction

```
PYTHONPATH=. python -m pytest tests/test_meshquality_numpy_backend.py -q
PYTHONPATH=. python scripts/meshquality_numpy_benchmark.py     # regenerates section 3
```
