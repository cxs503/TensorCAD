# Righting arms: the PR #52 disposition, and the third integration

This page records what happened to PR #52 and where its substance went. The short
version: the *module* it proposed is a duplicate and was retired; the *method* it
carried is now the third, independent integration that cross-checks the canonical
one, and its evidence — the convergence study, the deck-edge onset, the closed-form
ladder — was re-measured on the canonical meshes and is published under
[`docs/righting/`](righting/report.md).

## What PR #52 proposed

`agent/m3581` (`b691ce4`, "Righting arms: GZ curve by heeled-section integration",
0.21.0) added a 725-line `tensorcad/righting.py` that computes `GZ(phi)` by a route
of its own:

* cut the mesh into station outlines with `tensorcad.bonjean.section_loops`;
* clip each polygon against the tilted half-plane `z cos(phi) - y sin(phi) <= offset`
  with Sutherland–Hodgman and take its area and first moments by Green's theorem;
* integrate the station areas and moments along the hull with composite Simpson, which
  gives the heeled volume and `y_B`, `z_B` in one pass;
* find the offset that holds the displacement constant by bisection, then
  `GZ = (y_B - y_G) cos(phi) + (z_B - z_G) sin(phi)`.

plus a 446-line test module, an example with a station-convergence study, and a
`docs/righting/` evidence bundle. All of that is sound work; the problem was the
*address* it landed at.

## Why the module could not be merged as proposed

Between the branch point and the current `main`, the same physics arrived twice more:

| route | module | method | status since |
|---|---|---|---|
| canonical | `tensorcad/gz.py` | closed-surface integration (divergence theorem, apex on the waterline), Newton on the wetted area for the waterline | canonical since 0.21; `docs/gz.md`, `examples/gz` |
| second | `tensorcad/righting_arm.py` | same region, integrated face by face in the body frame, bracket-and-bisect on the monotone `V(h)` | kept since 0.22.0 as a cross-check, names published as `bisection_righting_arm_curve`, `barge_wall_sided_righting_arm` so nothing shadows `gz` |
| retired | `tensorcad/righting.py` (this PR) | heeled sections + Simpson along the hull | **retired**: a third public route with colliding names (`righting_arm_curve`, `wall_sided_righting_arm`) adds surface, not information |

A third public module would have had to publish `righting_arm_curve` and
`wall_sided_righting_arm` again — the exact collision `0.22.0` fixed by aliasing the
second route — while computing the same lever from the same mesh. `main`'s rule, set
when PR #95's duplicate integrator was retired and its evidence ported onto
`tensorcad.gz`, is that a route earns a public name only if it answers a question the
canonical one cannot.

## What was kept, and where

* **The method, as an oracle.** [`examples/righting/oracle.py`](../examples/righting/oracle.py)
  is the station integrator, rewritten against today's API and documented as a
  verification oracle rather than a library entry point. Its error sources are
  disjoint from the canonical ones — longitudinal quadrature and polygonisation of
  the sections, versus surface triangulation and a waterline iteration — which is
  what makes agreement between them evidence rather than a tautology.
* **The evidence, on the canonical meshes.** [`examples/righting/run_example.py`](../examples/righting/run_example.py)
  re-measures the closed-form ladder on a box barge, the deck-edge immersion onset,
  the displacement bookkeeping, and the station-grid convergence, and adds the claim
  the original bundle could not make: the canonical curve and the station curve on the
  same hull. It writes [`results.json`](righting/results.json),
  [`report.md`](righting/report.md) and [`righting_arms.png`](righting/righting_arms.png),
  and exits non-zero if a claim breaks, so CI runs it as a gate rather than a demo.
* **The negative controls.** Two of them, because an agreement test that cannot fail
  is decoration: the wall-sided closed form must go *visibly* wrong one step past its
  validity window, and shifting the canonical route's displacement target by 2 % must
  move the curve.

The measured numbers live in [`docs/righting/report.md`](righting/report.md), which is
regenerated by the example on every run and guarded by `tests/test_righting.py`; they
are deliberately not copied into this page, so this page cannot drift away from them.

## How to reproduce

```bash
python examples/righting/run_example.py           # writes docs/righting/, exit code is the verdict
python -m pytest tests/test_righting.py -q        # 15 tests, ~3 s
```

## Scope, and what the comparison does *not* say

The oracle inherits the method's limits: sections must be single-valued in `z` per
`y` per station, so no overhangs and no immersed deck between the modelled sections;
`kg` is a load input above the keel and is never inferred; free surface, damage,
flooding, trim coupling and statutory criteria (IS Code 2008, SOLAS) are outside both
routes. Agreement between two integrators says the *integration* is right; it says
nothing about whether the hull, the loading or the criterion is the right one — that is
`docs/gz.md`'s subject, not this page's.
