# DTC hull file: present in the source cache, unreadable by this reader (measured)

Anchor **REPRO-GEOM-FLEET-REFS** (TensorCAD). Round 3 of the fleet-reference library recorded the
DTC geometry stage as `WITHHELD` with the reason *"no DTC hull IGES is reachable:
`www.uni-due.de/ship/dtc.php` returns HTTP 404"*. That reason was wrong about the **bytes** and
right about the **outcome** — for a different, measurable reason. This note replaces the
hand-waved withdraw with a pinned one.

Machine artefact: `benchmarks/verified/fleet_refs/dtc_geometry.json`
(re-generated by `python tools/baseline_fleet/dtc_archive_probe.py`, no number typed in by hand).
Guard under test: `tests/test_fleet_refs_dtc_geometry.py`.

## 1. Case

DTC (Duisburg Test Case, MOERI KCS-derived 13 000 TEU container ship, λ = 1/59.407) is one of the
six benchmark hulls of the fleet. The reference library already holds **two independent lineages**
for its displacement and block coefficient (table 3), so the missing half of the DTC story is not a
reference at all — it is the geometry that a reconstruction would be measured against.

The hull file *is* on disk. The workshop IGES archive is served from the INAM file area rather than
from the 404'ing page, and this environment's source cache holds it:

## 2. How it was measured

1. Read the hull file's IGES **D section** at fixed columns (bytes 1–8 of each directory line) and
   count entity types — no interpretation, just the census.
2. Sample its B-spline surfaces with the *same* call the `iges_field` route makes
   (`tensorcad.fleet_baseline.sample_patches`), then measure the axis extent of the resulting cloud.
3. Hand the file to the production route (`tensorcad.fleet.build.iges_field_mesh`) at model-scale
   settings (spacing 0.4 m, dx 0.4 m, dz 0.08 m, 60 ring points) and record what it does.
4. Repeat steps 2–3 on the **KCS** hull file as a control: it is a hull the same reader handles, so a
   zero cloud is attributable to the file rather than to the reader.

## 3. Results

Entity census of `DTC_hull.igs` (1 629 directory entries):

| entity type | count |
|---|---|
| 128 rational B-spline **surfaces** | 1 345 |
| 126 B-spline curves | 232 |
| 141/143 boundary + flags | 24 / 24 |
| 102/314/406 (transform, colour, property) | 1 / 1 / 2 |
| 144 trimmed patches | **0** |

Sample census (model scale, spacing 0.4 m):

| file | B-spline surfaces read | sample points | distinct points | max axis extent |
|---|---:|---:|---:|---:|
| `DTC_hull.igs` | 1 345 | 448 590 | **1** | **0.000 m** |
| `KCS_hull_SVA.igs` (control, 0.5 m) | 55 | 33 666 | many | **243.854 m** |

Route outcome on the DTC file: **`RouteRefusal` — "IGES sampling collapsed to a point"**.

So: the file is a valid IGES archive with 1 345 surface entities, and this repository's reader
evaluates every one of them to the origin. Before this round the route did not notice: it would
have lofted the all-zero cloud into a closed, watertight, zero-volume "hull" that passes the
topology gates and fails only as an unexplained −100 % volume error.

## 4. What changed in the code

`tensorcad/fleet/build.py` now measures the sample cloud before the field stage
(`_sample_extent`) and refuses when the cloud's largest axis extent is below `1e-6 · max(L, 1 m)`:

```
IGES sampling collapsed to a point: 448590 sample(s) from 1345 B-spline surface(s) of
…/DTC_hull.igs span 0.000e+00 m (hull length 355.0 m); the surface entities could not be evaluated
```

The threshold is a collapse test, not a plausibility test: a hull whose sampled extent is a
millionth of its length is not a hull, while a coarse sampling of a real hull is hundreds of
times larger. Nothing else about the route changes; a healthy file (the KCS control) samples and
lofts exactly as before.

## 6. Error judgement

| quantity | value | criterion | verdict |
|---|---|---|---|
| DTC sampled extent vs KCS control extent | 0.000 m vs 243.854 m | > 100 m for a real hull | **file unreadable** |
| DTC mesh volume vs published ∇ (173 468 m³) | — | < 1 % | **not run** (route refuses) |
| DTC ∇ published range between lineages | 2.9e-6 | < 0.5 % | **pass** |
| DTC Cb published agreement | 0.0 | < 0.5 % | **pass** |
| < 3 % claim on any DTC *measured* quantity | — | < 3 % | **cannot be made**: nothing measured |

Limits of this finding: the cause of the zero evaluation is not diagnosed here (a plausible
candidate is a control-point/field layout in the CATIA export that `tensorcad.iges` reads as
zeros for type 128, but that is a hypothesis, not a measurement); the parser fix is future work,
and until it lands DTC stays a reference-only hull. No other hull's results are affected — KCS,
KVLCC2, JBC and ONRT are measured through their own files and their own rounds.
