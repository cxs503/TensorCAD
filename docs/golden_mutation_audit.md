# Golden gate mutation audit — does the geometry gate have teeth?

Anchor: `GAP-CAD-D2-GOLDEN-REGRESSION` (golden library + CI for any `tensorcad` geometry change).

Machine-readable record, regenerated by `tools/golden/mutation_audit.py`:

| artifact | what it is |
| --- | --- |
| `docs/golden/mutation_audit.json` | full audit record: controls, per-metric envelope, policy, violations |
| `docs/golden/mutation_audit.md` | the same, rendered as a report (generated, never hand-edited) |
| `docs/golden/mutation_audit.png` | declared tolerance vs measured threshold, and the per-metric blind spot |
| `tests/test_golden_mutation.py` | the audit as a test: 11 assertions including "the committed report is the one this code produces" |

## 1. The gap this closes

`tests/test_golden_regression.py` (40 tests) already proves the *harness* fails closed: a
missing, unreadable, stale or wrong-schema baseline is an error; a hand-edited reference is
rejected; `--bless` refuses a tree that fails its own gate; the git hook and the CI workflow
are wired to geometry paths. Every one of those negative tests injects either a synthetic
probe case (`ProbeCase`) or a tampered baseline file.

So the suite proved everything except the property the gate exists for: **if the geometry
code regresses, does the gate notice?** A gate whose only demonstrated failures are ones it
was told to produce is not evidence.

## 2. Method

Two batteries, both driven through the real gate (`tensorcad.golden.run_suite` /
`evaluate_case`) against the committed baseline — no reimplementation of the criterion.

**Battery A — library binding.** Push a 0.1–1 % mutation into the *real* entry point a
golden case calls, then run the untouched gate:

| control | mutation | case |
| --- | --- | --- |
| `sphere_volume_scaled_1.01` | `hydrostatics.compute_hydrostatics` returns 1 % more displacement | sphere/ellipsoid |
| `series60_waterplane_scaled_1.002` | `series60.generate_series60` reports waterplane +0.2 % | Series 60 |
| `wigley_volume_scaled_0.99` | `wigley.generate_wigley` loses 1 % displacement | Wigley |
| `dtmb5415_cb_scaled_1.001` | reported `cb` decoupled from its own volume by 0.1 % | DTMB 5415 |
| `dtmb5415_shell_scaled_1.001` | shipped shell scaled 1.001 in every axis | DTMB 5415 |
| `no_mutation_control` | none — must still pass | Series 60 |

Each control runs the *whole* suite, so a failure that spreads to another golden case is
itself a finding (case entanglement).

**Battery B — self-blessed blind-spot envelope.** The drift layer compares against the
blessed measurement at 1e-9, so it catches any reproducible change. The adversary that
matters is the developer who answers a red gate with `--bless`. For every asserted analytic
metric, the measured value is scaled by `1 + δ` on both grid levels, the baseline is
re-blessed exactly as `--bless` would write it, and the gate is re-run. Two adversary
classes are separated:

- **coherent** — the reported numbers stay mutually consistent (`V = Cb·L·B·T`,
  `Cb = Cp·Cm`, mesh extent `= 2 ×` cloud extent all still hold), so the identity layer is
  blind by construction and only the accuracy tolerance decides. This is what a wrong scale
  factor, a stale coefficient, or a mis-wired formula looks like from outside.
- **incoherent** — one number is reported inconsistent with the rest. An identity is exact,
  so it must fire orders of magnitude below the accuracy tolerance.

The δ ladder is anchored at 0.1 / 0.2 / 0.5 / 0.9 / 1.0 / 1.1 / 1.5 / 2 / 3 / 10 × the
metric's own tolerance, so a threshold that is *not* the tolerance appears as a bracket miss
rather than as sweep noise. Cost is kept at ~30 s by measuring each hull once and reusing
the cached measurement for all ~900 re-blessed evaluations.

## 3. Results

- Battery A: **6/6**, including the no-mutation control; every mutation is localised to its
  own case, so no golden case is entangled with another.
- Layers *shown* to work end to end: accuracy (`reference_mismatch`), invariant
  (`invariant_violated`), drift (`drift`), reference (`reference_not_reproducible`).
- Battery B, 25 metrics swept: the measured threshold coincides with the declared tolerance
  for every metric whose own tolerance is the binding criterion (e.g. Wigley displacement
  tolerance 4.33e-3 → threshold 4.33e-3; sphere volume 5.46e-3 → 6.00e-3, the small excess
  being the one-sided room left by a baseline that already sits 8.9e-4 below its reference).
- Metrics inside an identity cone are caught **earlier** than their own tolerance, by the
  tightest member of the cone: Series 60 volume/`Cb` (tolerance 1.83e-2) are caught at
  1.0e-4 by `Cp`/waterplane (2.06e-4) and, incoherently, at 1e-9 by the identities.
- Median blind spot 2.27e-4; worst 2.72e-2.

## 4. Findings and honest limits

1. **One metric admits a coherent regression above 1 %: `series60/maximum_section_area_m2`,
   blind spot 2.72e-2.** Its tolerance is 1.81e-2 because it is twice the coarse-to-fine
   change measured between the 81×25 and 161×49 grids; the baseline error is −8.56e-3, which
   leaves extra room on the positive side. It is listed in
   `docs/golden/mutation_audit.json:blind_spots_ge_1pct` and must stay listed until the
   criterion changes. Nothing is hidden; the claim "no 1 % bug can pass" is simply **false
   for this metric** and the report says so.
2. **The two-grid tolerance is a legitimate but loose bound** (2 × the coarse-to-fine
   change, with a 1e-4 floor). A tighter criterion needs a third grid level and a Richardson
   estimate of the remaining error, which would also require re-blessing the baseline; not
   attempted here. This is the concrete follow-up.
3. **Battery B perturbs reported numbers, not the geometry.** It bounds what the *criterion*
   can see given a reported value; battery A is what binds the criterion to the library. Both
   are needed, and neither alone is sufficient.
4. **Battery A uses `_Scaled` proxies** rather than edits to `tensorcad`, so it proves the
   gate reads the library's numbers, not that a specific arithmetic mistake in a kernel is
   caught. A kernel-level mutation study (e.g. wrong Simpson weights) remains open.

## 5. Verdict

Policy (blocking): every battery-A control detected and localised, the no-mutation control
clean, the declared tolerance within the ladder bracket of the measured threshold, identity
participants catching an incoherent report by 1e-3, and coherent maps provably invisible to
the identity layer.

**0 violations.** The gate is bound to the library it guards, its identities give early
warning, and its declared tolerance — not something looser — is the threshold that decides,
with the single documented exception above.

## Reproduce

```sh
python tools/golden/mutation_audit.py --check \
    --json docs/golden/mutation_audit.json \
    --md docs/golden/mutation_audit.md \
    --figure docs/golden/mutation_audit.png
python -m pytest tests/test_golden_mutation.py tests/test_golden_regression.py -q
```

CI: the `mutation-audit` job in `.github/workflows/golden-geometry.yml` runs on every change
to `tensorcad/**`, `tools/golden/**`, `docs/golden/**` or the golden tests, publishing the
table in the job summary.
