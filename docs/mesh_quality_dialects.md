# Aspect-ratio dialects: three numbers, one algebra, a provable threshold transfer

*Mission:* `GAP-CAD-D1-MESH-QUALITY-LIB` (selfstart m18708). *Code:*
`tensorcad/meshquality/dialects.py`. *Evidence:* `artifacts/mesh_quality_dialects/audit.json`
(+ `dialects.png`, `manifest.json` with sha256), regenerated by
`python tools/aspect_dialect_audit.py` (exit 1 on any failed criterion).
*Tests:* `tests/test_meshquality_dialects.py` (19).

## 1. The problem this closes

Finding **F1** of `docs/mesh-quality-lib-audit-m17404.md` was that the repository ships
`aspect = l_max²/(2A)` in `mesh_conditioning`/`validation` while the canonical library ships
a differently normalised number, and that a threshold copied between them silently relaxes
the gate. Finding **F4** was that the duplicated definitions were left in place with nothing
preventing a further one.

While relating the dialects it became clear the problem is larger than F1 recorded: **the
two modules that each call themselves canonical disagree with each other on the same
element.** On the 45-45-90 triangle that is half a unit square (the actual shape of every
triangle in `box_unit`):

| dialect | definition | producer | value |
|---|---|---|---|
| `legacy` | `l_max² / (2A)` | `mesh_conditioning._aspect_ratio`, `validation.measure_quality` | 2.000000 |
| `edge_form` | `l_max·p / (4√3·A)` | `geomquality.quality.triangle_quality` | 1.393847 |
| `verdict` | `R / (2r)` | `meshquality.metrics.tri_metrics['aspect_ratio']` | 1.207107 |

Spread 1.66×, and **neither** canonical module is normalised to 1 at the ideal element for
the legacy dialect (there it reads `2/√3 = 1.1547`). So "ideal value 1" — the one property
every dialect satisfies in principle — cannot be used to tell them apart, which is exactly
how two canonicalisations appeared side by side.

## 2. The algebra (exact, not fitted)

With `p` the perimeter, `l_max` the longest edge, `A` the area, `R` the circumradius:

```
edge_form = legacy · α,      α = p / (2√3 · l_max)          α ∈ [1/√3, √3/2]
verdict   = edge_form · β,   β = √3 · R / l_max             β ∈ [√3/2, ∞)
verdict   = legacy · α · β                                  verdict/legacy ≥ 1/2
```

Bounds and their proofs:

* `l_max ≤ p/2` and `l_max ≥ p/3` ⇒ `α ∈ [0.5773502691896258, 0.8660254037844386]`;
  the minimum is a collinear triangle, the maximum the equilateral one.
* `l_max ≤ 2R` ⇒ `β ≥ √3/2 = 0.8660254`; the minimum is any right triangle whose
  hypotenuse is the circumdiameter (the 45-45-90 above), and there is **no** upper bound
  because a sliver's circumradius is unbounded.
* The two minima are attained by different triangles, so `verdict/legacy ≥ 1/2` is the
  safe combined statement rather than a tight one.

All three equal 1 only in the sense that they order elements identically at the ideal
element; numerically only `edge_form` and `verdict` read 1 there.

## 3. What the code does about it

`conservative_limit(limit, target=…, source="legacy")` returns the limit in another dialect
that **cannot** pass an element the source gate would reject, using the proved worst case:

| source → target | factor | value for legacy 25 |
|---|---|---|
| `legacy → edge_form` | `α_min = 1/√3` | **14.4338** |
| `legacy → verdict` | `1/2` | **12.5** |
| `edge_form → legacy` | `√3` | 43.3013 |
| `verdict → legacy` | `2` | 50.0 |
| `edge_form → verdict` | `β_min = √3/2` | 21.6506 |
| `verdict → edge_form` | none (β unbounded) | `0.0` — reported, not invented |

Copying 25 into `edge_form` or `verdict` instead is what F1 measured as unsafe; §4 counts
the elements where it actually flips a verdict.

`legacy_aspect_from_metrics(area, longest)` now holds the single arithmetic expression
`longest*longest/(2.0*area)`, and both production modules delegate to it
(`validation.measure_quality`, `mesh_conditioning._aspect_ratio`). That closes F4 for the
legacy dialect and makes the delegation a **no-op on the numbers**, verified as identity
below rather than as a tolerance on a report.

Identity with the production modules on every element of every mesh: worst relative
difference **8.2e-16** (`legacy` vs `validation.measure_quality`, `edge_form` vs
`geomquality.quality`, `verdict` vs `meshquality.metrics`). The bounds hold everywhere, and
the conservative limits pass **zero** elements beyond the legacy gate — a self-check of the
proof, since the same sweep with the copied limit does flip one element of `random_soup_400`.

The hull meshes carry no flip only because their worst aspect ratio (8.1) is far below 25;
the auditor's finding was measured on `suboff_coarse`, whose worst is 14826, so the flip
count there is a property of the mesh, not of the dialect.

## 5. Notes, limits, applicability

* **What is proved:** the two bounds (Euclidean, three lines of algebra each), the transfer
  factors, and that the delegation reproduces the shipped numbers exactly.
* **What is not:** which dialect VTK's `vtkMeshQuality` — and therefore `meshmagick`'s
  `print_quality()` — actually calls "Aspect Ratio". `vtk`, `gmsh` and `meshmagick` are
  absent on this loongarch64 host and the package index (`lpypi.loongnix.cn`) carries none
  of them, so the two canonical numbers are exposed under neutral names and the
  attribution stays **unverified** (finding F3 status). No claim in this document depends
  on which one VTK uses.
* **Not changed on purpose:** the numbers emitted by `geomquality.quality` and
  `meshquality.metrics` are untouched, because changing either would change the gates and
  reports already published on them. This change adds the relation and the safe transfer;
  it does not renumber history.
* The `verdict → edge_form` conversion returns `0.0` with its reason instead of a large
  number, because no finite edge_form limit is provably stricter: a sliver can have an
  arbitrarily large `R/l_max`.

|---|---|---|---|---|
| `legacy` on 45-45-90 | closed form `l_max²/2A = 2` | 2.000000 | 0 | yes |
| `edge_form` on 45-45-90 | closed form `l_max·p/(4√3A)` | 1.3938469 | ≤1e-15 rel | yes |

| α bounds | `[1/√3, √3/2]` proved | observed `[0.5781, 0.8540]` ⊂ band; both ends attained by constructed elements | 0 violations | yes |
| β bound | `≥ √3/2` proved | observed min `0.8660254` (= 45-45-90), 400 random triangles | 0 violations | yes |
| production identity | `validation` / `geomquality` / `meshquality` | same three numbers, 3090 elements × 5 meshes | worst **8.2e-16** rel | yes (by 13 orders) |
| vs gmsh / meshmagick / VTK | external oracle | **not run** — no wheel for loong64, no source host available | n/a | **cannot be answered; not a pass** |

The last row is the honest remainder of the anchor's acceptance criterion
("与 meshmagick+Gmsh 指标对拍"): the differential is still **not run**, and this work does not
claim it. What it removes is the *reason it was blocked from being meaningful* — the
in-repo definitions no longer disagree about what the number means, so an external
comparison now has a single quantity to compare against.
