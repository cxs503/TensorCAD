# STL 腿的双编码矩阵与 float32 量化包络（锚点 GAP-CAD-B2-MESH-FORMAT-MATRIX）

**Mission**: m23297 · **仓库**: TensorCAD · **提交对象**: `agent/m23297` · **工具链**: Python 3.11.6 / meshio 5.3.5 / numpy 2.4.6 (loongarch64)

---

## 1. 案例介绍

### 1.1 为什么这单要重验 STL 腿

`GAP-CAD-B2-MESH-FORMAT-MATRIX` 的验收是「6 格式 × 3 几何 = 18 组合全绿表」，
STL 在表里只占一行。但 STL 这个名字下面是**两种线格式**，它们在往返保真上不是同一件事：

| 编码 | 坐标表示 | 往返误差 | 体积代价 | 谁在用 |
|---|---|---|---|---|
| ASCII STL | 十进制文本（`facet normal … vertex x y z`） | 精确（double→文本→double 无损失） | 大 | meshio 5.x 的默认输出 |
| binary STL | 80 字节头 + uint32 计数 + 每条 50 字节、坐标 float32 | 有损，误差 = `2^-24·|coord|`（**绝对**误差，随坐标偏移增长） | 小 | CAD 系统、3D 打印、多数交换场景 |

已发布的全绿表（`docs/mesh_format_matrix.md` 及后续各期）的 STL 行全是**走 meshio 默认输出**，
在 meshio 5.x 上默认是 **ASCII**：实测 4 个几何体写成 STL 都以 `solid` 开头、可整段 UTF-8 解码。
与此同时文档里的精度陈述——「binary STL 用 float32，相对误差上限 `3×eps32 ≈ 3.6e-7`」——
讲的却是 **binary** 编码。两处证据没有绑在同一个产物上：表格测的是 ASCII，结论说的是 binary。

### 1.2 物理背景与船舶相关性

船体几何在船厂/CFD 工具链里交换时，坐标通常不在原点附近：典型船体在 `x∈[0, 300] m`，
若按总布置/全球框架（ENU、分段坐标系）给出，坐标量级可达 `10^2–10^4 m`。
float32 在 `|x|=10^3 m` 处的网格间距是 `6.1e-5 m`——比船体表面曲率分辨尺度小不了多少，
在 `|x|=10^4 m` 处是 `6.1e-4 m`。所以「binary STL 精度够不够」不能一句话回答，
必须给出**随坐标量级变化的包络**。

### 1.3 参数表

| 项 | 取值 |
|---|---|
| 几何体 | cube, sphere, capsule, wigley_hull（unit cube / unit sphere / capsule L=4 r=0.5 / Wigley hull L=10 m B=1 m T=0.625 m，1001 节点 1998 三角形） |
| 编码 | ascii / binary |
| 坐标偏移 | x += 0, 10, 100, 1000, 10000 m |
| float32 单位舍入 | eps32 = 2^-24 = 5.960464e-08 |
| 记录数 | 40 = 4 几何 × 2 编码 × 5 偏移 |

## 2. 怎么做的

### 2.1 流程

1. **编码补全**：`tensorcad.meshio_exchange.write_meshio` / `round_trip_meshio` 新增
   `stl_binary: bool | None` 开关（仅 STL 合法，对 obj/vtk/gmsh/su2/cgns 直接 `MeshioFormatError`，
   不允许其它格式静默继承 STL 的开关）。`None` 保持 meshio 默认（ASCII）以不改变既有证据链。
2. **量化预检**：新增 `stl_quantisation_bound(mesh, encoding=…)`，给出
   `max_coordinate_error = eps32·max|x|`、包围盒对角、最细棱长、
   `screening_volume_rel_error = 2·max_coordinate_error/diagonal`（保守估计），
   以及 `distinct_vertices_may_merge`（量化台阶 ≥ 最细棱长 ⇒ 两个节点会被 float32 合并，
   拓扑会**静默改变**）。
3. **缺陷修复**：`tensorcad.mesh_foreign_dialects.write_stl_binary` 原来先用 float64 坐标算
   面法向、再把坐标转 float32——文件里的法向描述的是**不在文件里的**那个三角形。
   改为先 `astype(float32)` 再用量化后坐标算法向（本单实测：偏差从随偏移增长到 7.9e-3，
   降为与偏移无关的 4.1e-8）。
4. **测量**：`scripts/stl_encoding_matrix.py` 对 40 个组合写出真实文件、读回、量体积/坐标/法向，
   并用 `tensorcad.mesh_foreign_dialects.read_stl_binary`（手写规范解析器，**不经 meshio**）
   独立复算体积与法向一致性，产物落在 `runs/m23297_stl_encoding/`（含 40 个 STL 的 sha256）。
5. **回归**：`tests/test_stl_encoding_matrix.py`（39 例）+ 既有格式矩阵/外来方言测试。

产物：`artifacts/m23297_stl_encoding/matrix.json`（40 条测量记录，含每个 STL 的 sha256）、
`artifacts/m23297_stl_encoding/stl_payloads.tar.gz`（40 个 STL 实体，供第三方重读）。

### 2.2 关键设置

- 体积一律用 `surface_signed_volume`（散度定理），参考值取**变换前同一个体**的闭壳体积，
  所以偏移带来的几何变化不会混进误差里；ASCII 的 `relV = 0` 也因此是真正意义的 0，不是容差内。
- 顶点比较前先按列排序：meshio 的 STL 读入会把重复节点合并并重编号，不排序就无法逐点比对。
- 取向判据用符号（`V_back·V_body > 0`），不用 `|V|`，否则整体翻面会被漏掉。

### 3.2 ASCII 默认腿的字节代价（interop cost）

| 几何体 | ASCII 字节 | binary 字节 | 倍数 |
|---|---|---|---|
| cube | 1438 | 684 | 2.10× |
| sphere | 671700 | 110484 | 6.08× |
| capsule | 454716 | 76884 | 5.91× |
| wigley_hull | 481816 | 99984 | 4.82× |

单位立方体只有 2.1×（坐标数字短、三角形少），船体是 4.8×、球 6.1×——
ASCII 是精确的，代价是体积；对 `x~10^3 m` 的船体，binary 把 482 KB 压到 100 KB，
但代价是 3.0e-5 m 的坐标量化，量级与某些表面加工公差同阶。

### 3.4 预检包络是否覆盖实测

binary 组合 20 个，预检上界**全部覆盖**实测（20/20）：
坐标误差逐例 ≤ `eps32·max|x|`，体积误差逐例 ≤ `4 ×` 预检体积估计。
同时预检对坐标本就 float32 可精确表示的几何体是**偏保守**的：单位立方体在 `x=10^4 m` 处
预检给 5.961e-04 m，实测 0（0 与 10^4 都能精确表示）。
上界保守是可接受的，反过来（预估小于实测）才不可接受——本表无一例。

## 5. 注意点

1. **被否定的既有陈述**：`docs/mesh_format_matrix.md` 的「binary STL 相对误差上限 3×eps32 ≈ 3.6e-7」
   作为**相对**误差上限不成立。它是坐标的**单位舍入**；相对体积误差在船体框架下实测到 5.85e-5
   （球体，`x=10^4 m`），比该上限大两个数量级。正确陈述是「绝对误差 ≤ eps32·max|x|，
   相对误差 ≈ eps32·max|x| / 体尺度」。文档已加更正注记。
2. **偏移方向的影响**：本表的偏移只加在 x 上。Wigley 船体的站号 abscissa 是 float32 可精确表示的，
   所以它在 x 平移下体积误差不变（1.95e-9）；换成 y/z 方向的错位或非精确坐标就会增长。
   预检取三轴 `max|x|`，不依赖偏移方向，因此对这类情形仍然安全（只是保守）。
3. **预检是筛子，不是证明**：`screening_volume_rel_error = 2·eps/diag` 是经验估计，
   在 4 几何 × 5 偏移上被实测覆盖（且留 4× 余量），但没有给出表面积/体积比放大因子的严格界。
   薄壁/长宽比极端的网格请以实测为准。
4. **`distinct_vertices_may_merge` 只报风险，不改行为**：写器不会因为该标志拒绝写文件——
   是否可接受是调用方（求解器门槛）的判断；测试里用一个 1e-7 间距的退化几何验证了该标志会亮。
5. **meshio 写器的法向缺陷没被修**：那是上游代码，本单只修 TensorCAD 自己的 `write_stl_binary`，
   并在证据表里把上游代价量化出来。要拿自洽的 binary STL，请走 `write_stl_binary`。
6. **默认仍是 ASCII**：不改默认是为了不推翻已发布证据链；需要 binary 时显式 `stl_binary=True`。

## 6. 误差判定（逐项 vs 基准，显式回答是否 <3%）

| 关键量 | 基准 | 实测 | 相对偏差 | <3%? |
|---|---|---|---|---|
| ASCII 往返体积（4 几何 × 5 偏移，20 组合） | 变换前闭壳体积 | rel err ≤ 0.000e+00 | 0 | **是（0%）** |
| binary 往返体积（同样 20 组合） | 同上 | rel err ≤ 5.847e-05 | ≤ 0.0058% | **是** |
| binary 独立解析器（手写规范解析，不经 meshio）复算体积 | 变换前体积 | rel err ≤ 5.847e-05 | ≤ 0.0058% | **是** |
| 文档所称 `3×eps32 = 3.6e-7` 相对界 | 球体 `x=10^3 m` binary 实测 | 4.958e-06 | 28× 超出 | **否——该界不成立（已更正）** |
| 面法向自洽（TensorCAD 写器） | 文件内量化坐标的缠绕法向 | ≤ 4.125e-08（与偏移无关） | ≈ float32 单位向量舍入 | **是** |
| 面法向自洽（meshio 写器，上游） | 同上 | ≤ 7.878e-03（`x=10^4 m`） | 约 0.45° | **否（上游缺陷，已量化）** |

结论：**ASCII 腿 0% 误差；binary 腿体积误差 ≪3%（最坏 0.0059%）**，
但「3.6e-7 相对界」这一陈述在船体框架下不成立，已在文档中更正为绝对误差界 + 随偏移增长的实测包络；
面法向自洽性是本单修掉的真实缺陷（meshio 写器同样缺陷保留并量化）。
