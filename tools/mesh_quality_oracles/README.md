# Mesh-quality oracles — build and run

The differential `tools/mesh_quality_external_diff.py` compares
`tensorcad.meshquality` against the two tools the anchor names (meshmagick and Gmsh).
Neither ships on this image, so the *code they execute* is built here instead:

* **Verdict** (Sandia) — the definitions of `vtkMeshQuality`, which is what
  `meshmagick.print_quality()` delegates to.
* **Gmsh** — a harness over `libgmsh` calling `gmsh::model::mesh::getElementQualities`.

Nothing is vendored into this repository: third-party code, third-party licence, tens of MB.

## Mesh file format (`mq-mesh v1`)

Plain text, one item per line, 0-based node indices:

```
# mq-mesh v1
nodes <N>
x y z            (N lines, repr() floats)
<kind> <M>       (kind ∈ tri quad tet hex prism pyramid)
i j k …          (M lines, one element each)
```

Multiple `<kind> <M>` blocks may follow one `nodes` block.

## Oracle 1 — Verdict

```bash
curl -L -o verdict.tar.gz https://codeload.github.com/sandialabs/verdict/tar.gz/refs/heads/master
tar xzf verdict.tar.gz                       # -> verdict-master/  (commit 3474333 at time of writing)
# verdict_config.h is generated by CMake; a plain build needs it, so derive it from the template:
sed -e 's/@[A-Za-z_]*@//g' -e 's/#cmakedefine.*//' verdict-master/verdict_config.h.in > verdict-master/verdict_config.h
g++ -O2 -std=c++17 -Iverdict-master \
    verdict-master/V_*.cpp verdict-master/VerdictVector.cpp gmsh_verdict_harness.cpp \
    -o bin/verdict_oracle
```

`VerdictVector.cpp` is required: `V_*.cpp` does not match it, and without it `VerdictVector::normalize()`
is undefined. `-std=c++17` is required: `VerdictVector.hpp` declares `constexpr void` members,
which C++11 rejects.

## Oracle 2 — Gmsh

```bash
# native loong64 library + headers (Debian pool; .deb = ar archive, no dpkg needed)
curl -O https://deb.debian.org/debian/pool/main/g/gmsh/libgmsh4.15_4.15.2+ds1-1_loong64.deb
curl -O https://deb.debian.org/debian/pool/main/g/gmsh/libgmsh-dev_4.15.2+ds1-1_loong64.deb
python3 - <<'PY'   # extract data.tar.xz from each .deb
import io, tarfile
def members(buf):
    assert buf[:8] == b"!<arch>\n"; i = 8
    while i + 60 <= len(buf):
        hdr = buf[i:i+60]; size = int(hdr[48:58].decode().strip())
        yield hdr[:16].decode().strip(), buf[i+60:i+60+size]; i += 60 + size + (size % 2)
for deb in ("libgmsh4.15_4.15.2+ds1-1_loong64.deb", "libgmsh-dev_4.15.2+ds1-1_loong64.deb"):
    for name, data in members(open(deb, "rb").read()):
        if name.startswith("data.tar"):
            tarfile.open(fileobj=io.BytesIO(data)).extractall("gmsh_pkg")
PY
g++ -O2 -std=c++11 -Igmsh_pkg/usr/include gmsh_oracle.cpp \
    -Lgmsh_pkg/usr/lib/loongarch64-linux-gnu -lgmsh \
    -Wl,-rpath,$PWD/gmsh_pkg/usr/lib/loongarch64-linux-gnu -Wl,--allow-shlib-undefined \
    -o bin/gmsh_oracle
```

**The build succeeds; loading does not, on this image.** `libgmsh.so.4.15.2` needs
`libfltk{,_images,_gl}.so.1.3`, `libcgns.so.4.5`, `libmetis.so.5`, `libvoro++.so.1`,
`libann.so.0`, `libalglib.so.4.7` and the OpenCASCADE `libTK*.so.7.9` set (≈20 libraries) plus
their X11/fontconfig chain — measured with
`LD_LIBRARY_PATH=gmsh_pkg/usr/lib/loongarch64-linux-gnu ldd libgmsh.so.4.15.2 | grep 'not found'`.
From Gmsh 4.15.2 **source** the same harness runs against a self-built library, e.g.

```bash
cmake -S gmsh_src -B gmsh_build -DENABLE_FLTK=OFF -DENABLE_OCC=OFF -DENABLE_CGNS=OFF \
      -DENABLE_METIS=OFF -DENABLE_ANN=OFF -DENABLE_ALGLIB=OFF -DENABLE_VOROPP=OFF \
      -DENABLE_BLAS_LAPACK=OFF -DENABLE_BUILD_SHARED=ON -DENABLE_PYTHON=OFF && \
cmake --build gmsh_build -j
```

## Run

```bash
python tools/mesh_quality_external_diff.py \
    --verdict-oracle bin/verdict_oracle --verdict-version "sandialabs/verdict@3474333" \
    --gmsh-oracle    bin/gmsh_oracle    --gmsh-version    "gmsh 4.15.2" \
    --require-oracles
```

or via the environment (`TP_VERDICT_ORACLE`, `TP_GMSH_ORACLE`, `TP_VERDICT_VERSION`,
`TP_GMSH_VERSION`). Exit codes: 0 agree / 1 mismatch / 2 required oracle did not run.
